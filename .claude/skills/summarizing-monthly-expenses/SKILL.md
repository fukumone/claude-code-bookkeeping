## 月次仕訳サマリー生成 + 年間台帳更新

対象: `$ARGUMENTS/` 配下の勘定科目フォルダ

### ワークフロー

1. **`python3 scripts/rebuild_ledger.py $ARGUMENTS` を実行する**
   - 月次CSVと年間台帳の両方をこれ1本で再生成する
   - **集計ロジックを本skill内で再実装しない。** その場で書いた集計は、書くたびに間違える可能性がある
   - 金額を読めないファイルがあるとスクリプトは何も書かずに中止する。
     その場合はファイル名を直してから再実行する（勝手に手集計で代替しない）
2. スクリプトの出力（勘定科目ごとの件数・合計）をそのまま読み取る
3. 除外されたファイル（`_重複` など）が報告されたら、内容を確認してユーザーに伝える
4. 仕訳サマリーテーブルを表示
5. **領収書が発生しない定期項目の追従を確認**（後述・必須）
6. **変更を git commit**（後述・必須）

### 出力されるCSV（参考・手で書かない）

`$ARGUMENTS/管理台帳_YYYYMM.csv`（集計行だけ。明細はファイル名が兼ねる）

```csv
勘定科目,件数,合計金額,借方,貸方
消耗品費,1,2970,消耗品費,事業主借
会議費,2,2370,会議費,事業主借
合計,3,5340,,
```

`YYYY/管理台帳_YYYY.csv`（3セクション: 勘定科目別 月次推移・件数推移・年間サマリー）

### サマリー表示（厳守）

| 借方 | 金額 | 貸方 | 金額 | 件数 |
|------|------|------|------|------|

### 命名規則に沿わないファイルの検出

集計前に、命名規則（`YYYYMMDD_取引先_金額.拡張子`）に沿わないファイルを検出し、報告する:

- 金額部分が異常に大きい（写真番号の可能性）
- 取引先名が汎用的すぎる（例: `CAFE_4XXX` のような連番）
- ファイル名の日付とフォルダの対象月が一致しない

該当ファイルがある場合は**画像を読み取って正しい内容を確認**してからリネーム・再分類する。

### 重複ファイルの判断基準

同一取引の重複（店舗レシート＋カード決済控え、同じレシートの撮り直し等）を判断する際は、以下の**すべて**を満たすこと:

| 条件 | 内容 |
|------|------|
| 1 | 年月日が一致 |
| 2 | 時分が一致（レシート印字時刻とカード決済時刻） |
| 3 | 金額が完全一致 |
| 4 | 店舗が同一（または決済端末が同一店舗） |
| 5 | 伝票番号・検収番号が一致（印字があれば） |

- 同じ日に同じ店舗を2回利用するケースがあるため、日付+金額+店舗だけでは不十分
- 撮り直した画像はハッシュ（md5）が違うので、ハッシュでは見つからない
- **重複と判断しても削除せず、ユーザーに確認を取ること**

### 領収書が発生しない定期項目の追従（厳守）

年間台帳を再生成したら、**必ず CLAUDE.md「領収書が発生しない定期項目」の表にあるCSVを開いて、最終記載月を確認する**。
これらは `images/` に画像が届かないため、画像の仕分けだけでは永久に更新されない。

処理:

1. 各CSVの最終記載月が、集計対象月に追いついているか確認
2. 遅れていれば**ユーザーに引落実績を確認してから**追記する（勝手に定額を積まない）
3. **引落日が未到来の月は計上しない。** 今日が8/15なら引落日20日の8月分は未計上が正しい。
   ユーザーが「完了」と答えても、記録上の引落日が未来なら再確認する
4. 証憑がないまま追記する場合、摘要欄に「本人確認による引落実績（YYYY/MM/DD時点）」と根拠を明記
5. 確定申告サマリーの経費セクションは**売上と同じ期間で揃える**。月次台帳が先に進んでも期間を勝手に延ばさない

### 訂正したら履歴に記録（厳守）

台帳の金額を訂正した場合、またはファイルを削除・移動・リネームした場合は、
リポジトリ直下の `訂正削除履歴.csv` に追記する（事務処理規程 第8条）。

```csv
対象ファイル,処理日,処理内容,理由,処理者,コミット
```

### 完了後は必ずコミット（厳守）

台帳・CSVを更新したら、`build_books.py`・`build_dashboard.py` で再生成し、**ユーザーの指示を待たずに** `git commit` する。
ただし `/update-expenses` から呼ばれたときはコミットしない（1回の依頼＝1コミットにするため、監督skillが最後にまとめてコミットする）。

```bash
git add -A && git commit -m "<日本語の要約>"
```

- 金額が動いた場合はメッセージに理由を必ず書く
- push は指示があったときのみ

### 注意

- 貸方は「事業主借」をデフォルトとし、異なる場合はユーザーに確認する
