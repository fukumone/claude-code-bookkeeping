## 経費エントリ検証

対象: `$ARGUMENTS/` 配下の全勘定科目フォルダ

### ワークフロー

1. 対象月フォルダのサブフォルダと画像ファイル一覧を取得
2. 各画像を読み取り、以下を抽出:
   - 日付、時刻、店舗名（発行元）、宛名、合計金額、伝票番号
3. ファイル名（`YYYYMMDD_取引先_金額.拡張子`）から抽出した値と比較
4. 勘定科目（フォルダ名）が CLAUDE.md の「勘定科目一覧」「勘定科目の判断基準」に合っているか検証
5. 不一致・疑義を一覧で報告

### 検証チェック項目

- **金額チェック**: 画像の合計金額 ≠ ファイル名の金額 → エラー
- **日付チェック**: 画像の取引日 ≠ ファイル名の日付 → エラー
- **発行元チェック**: 画像の発行元・宛名・対象期間 ≠ ファイル名の取引先・フォルダの科目 → エラー
- **科目チェック**: CLAUDE.md の判断基準に照らして妥当か

### 出力フォーマット（厳守）

問題なしの場合:
```
## 検証結果: YYYY年MM月

全XX件を検証しました。問題は見つかりませんでした。
```

不一致がある場合:
```
## 検証結果: YYYY年MM月

全XX件中、YY件に疑義があります。

| # | ファイル名 | 項目 | ファイル名の値 | 画像の値 | 判定 |
|---|-----------|------|--------------|---------|------|
| 1 | 20260115_CAFEEXAMPLE_680.pdf | 金額 | ¥680 | ¥6,800 | 不一致 |
| 2 | 20260108_COFFEEEXAMPLE_450.pdf | 科目 | 接待交際費 | → 雑費が妥当 | 分類誤り |
```

### 重複判断の基準

同一取引の重複（店舗レシート＋カード決済控え、同じレシートの撮り直し等）を判断する際は、以下の**すべて**を満たすこと:

| 条件 | 内容 |
|------|------|
| 1 | 年月日が一致 |
| 2 | 時分が一致（レシート印字時刻とカード決済時刻） |
| 3 | 金額が完全一致 |
| 4 | 店舗が同一（または決済端末が同一店舗） |
| 5 | 伝票番号・検収番号が一致（印字があれば） |

- 同じ日に同じ店舗を2回利用するケースがあるため、日付+金額+店舗だけでは不十分
- **重複と判断しても削除せず、ユーザーに確認を取ること**（確認後は `_重複` を付けて残す）

### ファイル変更後の管理台帳更新

検証の結果、以下のいずれかのファイル操作を行った場合は、**必ず `/summarizing-monthly-expenses YYYY/MM` を呼び出して**月次管理台帳および年間管理台帳を再生成する:

- ファイルのリネーム
- 勘定科目フォルダ間の移動
- `_重複` の付与
- 別月フォルダへの移動

集計ロジックを本skill内で再実装しないこと（二重管理になるため）。
ファイルを動かしたら `訂正削除履歴.csv` にも記録する（事務処理規程 第8条）。

### 誤格納の検出（厳守）

**ファイル名を信じず、必ず画像の発行元を確認する。** 中身が名前と違う事故は実際に起きる。

- 例: 社会保険料の領収書として保存したファイルの中身が、電気料金の領収書だった
  → 社会保険料を多く、水道光熱費を少なく計上していた
- したがって検証対象は経費フォルダだけではない。**社会保険料・医療費・寄付金フォルダにも
  年1回は同じ検証を適用する**（引数に `YYYY/社会保険料` 等を受けた場合も同様に処理）
- 発行元・宛名・対象期間がファイル名の分類と一致するかを見る。金額一致だけで合格としない

### 完了後は必ずコミット（厳守）

ファイルの移動・リネーム、またはCSVの修正を行ったら、**ユーザーの指示を待たずに**
`git commit` する。金額が動いた場合はメッセージに理由を必ず書く。push は指示があったときのみ。

### 注意

- 画像が不鮮明で読み取れない場合は「読取不可」と報告し、スキップしない
- 件数が多い場合は勘定科目フォルダごとに処理し、進捗を都度報告する
